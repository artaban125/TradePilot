# TradePilot 프로젝트 계획서 (초안 v0.1)

> 작성 기준: 노션 「프로젝트 계획서 템플릿」 서식 + 「프로젝트 기획보고서 (최종 제출용)」의 Must 요구사항(FR-01~FR-04)과 제외 범위
> 작성일: 2026.11.26 / 상태: **팀 상의용 초안**
> 표기: `(제안)` = 제가 채운 안이라 팀 확인이 필요함, `❓` = 결정이 필요한 항목

- 팀명 / 팀원: Eye2Text / 이규남, 한병준, 김종호
- 프로젝트명: TradePilot — VLM·LLM 기반 무역문서 분석 및 지능형 업무지원 서비스
- 계획 확정일: 12.03 (이후 변경은 아래 "변경 기록"에 사유와 영향을 남긴다)

### 기획보고서에서 가져온 범위

| ID | Must 기능 | 수용 기준 |
| --- | --- | --- |
| FR-01 | 문서 업로드 및 핵심 필드 추출 | 지정된 JSON 스키마 파싱 오류 0건 |
| FR-02 | 데이터 검증 (품목 금액 합산과 문서 총액 검산) | 추출 수치의 계산 오류 확인 |
| FR-03 | 한글 번역 및 거래정보 구조화 | 핵심 항목(당사자·품목·총액·결제 조건·마감일·배송)이 한글 결과에 누락 없이 매핑 |
| FR-04 | 쉬운 업무 해설 및 부서별 체크리스트 | ① 당사자·금액 흐름·결제 방법·기한이 들어간 해설 ② 부서별 체크리스트 |

- 비기능: 외부 클라우드 API 없이 사내 로컬 GPU에서 단독 구동, 단일 페이지 문서 처리 30초 이내
- 제외 범위: 통관·관세 신고 자동화, ERP·회계 연동, 영어 외 문서
- 추가 검토(시간 여유 시): 원화 환산 참고치, 거래 이력 DB 조회, 엑셀/CSV 내보내기 고도화

### 5. 리스크와 대체안

| 무역 필드 정답 데이터 부족 | 데이터셋에 Incoterms·HS 코드·신용장 등이 0건 (평가셋 100건 검색 결과) | 합성 템플릿으로 무역 필드 포함 문서와 정답을 함께 생성 | 무역 필드는 "있으면 추출"로 두고 평가는 기존 필드 중심 | 12.04 | 김종호 |

| GPU 메모리·응답 속도 부족 | RTX 4090에서 VLM·LLM 동시 상주 시 메모리 부족, 처리 시간 30초 초과 (VLM bf16은 문서당 약 9~12초 ✅) | LLM 4-bit 양자화, 순차 로딩, 이미지 해상도 제한 | 더 작은 LLM 또는 해설 생성 길이 축소 | 12.10 | 이규남 |
